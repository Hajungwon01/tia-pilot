# 교통영향평가 초안 자동화 (TIA Pilot)

서울 아파트 개발사업의 **교통영향평가서 초안**을 자동으로 만들어 주는 웹 서비스입니다. 1인 개발, 입력부터 Word(.docx) 보고서 초안까지 한 흐름으로 처리합니다.

## 한 줄 요약
"숫자는 코드가 계산하고, LLM은 문장만 쓰며, 쓴 문장은 다시 계산 결과와 대조한다."

## 왜 만들었나
교통영향평가서는 수치(발생교통량, 주차수요, 교차로 서비스수준)와 해석 문단이 섞인 긴 문서이고, 계산 기준(도로용량편람, 지침)이 엄격합니다. LLM에 통째로 맡기면 숫자를 지어내거나 해석이 뒤집히기 쉬워서, **계산은 규칙 코드로, 문장 작성만 LLM으로** 나누는 구조로 설계했습니다.

## 하는 일
- 사업 개요(세대수·연면적·평형·계획 주차)와 교차로 정보(교통량·차로·신호 현시)를 입력하면 대상 여부·평가 범위를 판정하고 발생교통량, 주차수요, 신호교차로 LOS를 계산합니다.
- 사업 미시행 / 시행 / 개선 후 3단계를 비교하고, 개선 시나리오(녹색시간 재배분, 신호주기 탐색, 차로 증설, 전용 좌회전 차로, 조합)를 지체 감소순으로 제시합니다. 전용 좌회전 차로는 설계 지침의 길이식으로 시행 가능성까지 표시합니다.
- 15분 단위 교통량 조사 CSV를 올리면 첨두 1시간, PHF, 접근로 교통량을 자동 추출합니다.
- 문제점·개선방안 문단은 LLM이 쓰고, 결과를 Word 초안으로 내보냅니다.

## 구조
Planning → Data → AI → Engineering → Reflection 파이프라인이 하나의 상태 객체(`ReportState`)를 순서대로 채웁니다. **LLM은 AI 단계 한 곳에서만** 쓰고, 나머지는 모두 코드입니다. 점검에서 걸린 섹션만 사유와 함께 다시 쓰게 하는 재시도 루프가 있습니다. (흐름도: `docs/flow.html`)

## 핵심 기술 판단
**1. 계산 엔진을 편람 기준으로 직접 구현**
도로용량편람(2013) 제8장의 신호교차로 방법(좌회전 CASE 1~6, 직진환산, 보정계수, 연동계수, 초기대기지체)을 구현했습니다. 편람의 풀이 예제 2건으로 값이 일치하는지 검증했습니다. 예제 표와 본문이 서로 어긋난 곳(우회전 차로수)은 임의로 맞추지 않고 문서에 기록했습니다.

**2. 근거 있는 원단위**
국토교통부 교통영향평가정보지원시스템의 공개 유사시설 조사(아파트 278곳)를 수집해, 최근 3년·서울 우선·중앙값 방식으로 원단위를 정했습니다. 재차인원, 직접 조사한 원단위, 수단분담 같은 값은 사용자가 직접 입력할 수 있고, 근거 상태(확정/임시)와 불확실성을 결과에 표시합니다.

**3. LLM 환각 점검 (수치 + 해석)**
- 문장의 단위 붙은 숫자가 계산 결과에 없으면 걸러내고, v/c가 1 미만인데 "용량 초과"라고 쓰면 걸러냅니다.
- 실제 LLM(gpt-4o-mini)을 돌려 보니 **수치는 맞는데 해석이 뒤집힌 문장**이 나왔습니다. (법정의 124%인 주차를 "부족"으로 서술, 자료 없는 대중교통 이용 수준 단정, 유입·유출을 시간 증가로 풀이)
- 파인튜닝 대신 두 가지로 고쳤습니다. 입력에 판단을 코드로 확정해서 주고(`[주차 판정]`, `[자료 없음]`, `[분석 시간대]`), 방향이 뒤집힌 문장을 찾는 규칙을 추가했습니다.
- 이후 입력을 바꿔 다시 돌려 새 오류 유형(분석하지 않은 첨두 서술, 준공 연도 혼용, 계획 미입력 시 증설 제안)을 찾아 같은 방식으로 고쳤고, 점검 규칙 자체의 **오탐**(올바른 문장을 막는 경우)도 함께 수정했습니다. 출력이 호출마다 달라 한 번의 성공이 아니라 반복 측정으로 확인했습니다.

**4. 견고성**
무작위 입력(퍼징)으로 NaN·무한대가 나오는 구간을 찾아 고쳤고, 입력 검증 실패는 이유를 포함해 돌려줍니다. 모든 결과는 로그인 사용자별로 분리해 SQLite에 저장하고 TTL로 만료합니다.

## 검증 현황
- 자동 테스트 454건 통과
- 신호교차로 계산: 편람 풀이 예제 2건과 일치
- Word 출력: 실제 Word에서 렌더링 확인 후 표 폭 문제 수정
- 배포 준비(Railway), 배포 전 점검 스크립트 포함

## 한계 (정직하게)
- 실제 심의 사례(비공개 평가서)와의 결과 비교는 하지 못했습니다. 계산식 검증은 편람 예제까지입니다.
- 현장 조사와 도면은 만들지 못하고, 우회전 2차로 이상 공용은 편람에 식이 없어 지원하지 않습니다.
- 유사시설 '발생원단위'의 방향(유입 기준 vs 양방향 합계)은 공식 문서로 확정하지 못해 문헌 근거로 정하고 경고로 표시합니다.
- LLM 점검 규칙은 지금까지 본 오류 유형만 잡습니다.
