# 배포 가이드 (Railway)

마감: 2026-11-30. 이 문서는 Railway 기준이에요. **굵은 글씨의 "직접"** 표시는 사람이 해야 하는 단계예요(계정·결제·비밀 값 입력).

## 0. 먼저 알아 둘 구조 제약

- 저장소는 **SQLite 파일 하나**예요. Railway 볼륨은 서비스당 1개이고, **볼륨을 쓰면 복제본(replica)을 늘릴 수 없고** 재배포 때 잠깐(수 초~) 중단돼요(공식 문서). 이 서비스는 **인스턴스 1개**로 운영하는 게 맞아요.
- 볼륨 없이 띄우면 앱은 시작되지만 **재배포할 때마다 분석 결과가 사라져요**(컨테이너 디스크는 임시). 결과는 72시간만 보관하는 임시 데이터라 큰 문제는 아니지만, 초대 코드 사용자별 분리 데이터가 날아갈 수 있어요.
- 빌더는 Railway 기본인 **Railpack**이에요. 저장소 루트의 `requirements.txt`로 Python 앱을 감지하고, `.python-version`(3.12)으로 버전을 정하며, 시작 명령과 헬스체크는 `railway.json`에 들어 있어요. (Dockerfile을 추가하면 Railway가 그걸 우선 사용하니 넣지 마세요.)

## 1. 배포 전 로컬 점검 (제가 만든 스크립트)

비밀 값 생성 — 터미널에만 출력되고 파일에는 쓰지 않아요.

```bash
python scripts/predeploy_check.py --gen
```

운영용 환경변수를 임시 파일(`prod.env`, **git에 올리지 마세요**)에 적고 점검해요.

```bash
python scripts/predeploy_check.py --env-file prod.env
```

점검 항목: APP_ENV·초대 코드·SECRET_KEY 규칙, LLM 키와 접근 코드, 프록시 설정, DB 경로, 데이터 파일 존재, 그리고 **운영과 같은 설정으로 앱을 실제로 실행**해서 로그인·분석(mock)·Word 다운로드·다른 사용자의 보고서 접근 차단·API 문서 비노출·보안 헤더를 확인해요. FAIL이 있으면 종료 코드 1이에요. 점검은 LLM을 호출하지 않아요.

## 2. Railway 설정

1. **직접** Railway 계정을 만들고 GitHub 저장소 `Hajungwon01/tia-pilot`(master)를 연결해 새 프로젝트를 만들어요. (비공개 저장소라 Railway에 GitHub 접근을 허용해야 해요.)
2. **직접** 서비스에 **Volume**을 추가하고 마운트 경로를 `/data`로 해요. (Railway 화면의 메뉴 이름은 바뀔 수 있어요.)
3. **직접** Variables에 아래 표의 값을 입력해요. 비밀 값은 채팅·이슈·커밋에 남기지 마세요.
4. 배포가 끝나면 서비스 설정에서 공개 도메인을 생성해요(HTTPS 자동). 세션 쿠키가 `Secure`라서 **HTTPS가 아니면 로그인이 유지되지 않아요.**

### 환경변수

| 이름 | 값 | 필수 | 설명 |
|---|---|---|---|
| `APP_ENV` | `production` | 필수 | production이면 BETA_CODES·SECRET_KEY가 없을 때 앱이 시작되지 않아요(공개 사고 방지) |
| `BETA_CODES` | `코드1,코드2,…` | 필수 | 사용자마다 하나씩. 8자 이상 무작위 권장. 코드를 바꾸면 그 사용자의 로그인이 끊겨요 |
| `SECRET_KEY` | 32자 이상 무작위 | 필수 | 세션 쿠키 서명. 바꾸면 모든 로그인이 끊겨요 |
| `DB_PATH` | `/data/app.db` | 필수 | 볼륨 안의 경로여야 재배포 후에도 남아요 |
| `TRUST_PROXY` | `true` | 권장 | 프록시 뒤에서 로그인 시도 제한(10분에 10회)이 실제 접속자 IP로 동작 |
| `OPENAI_API_KEY` | (비움) | 선택 | 비우면 mock 모드(과금 없음). 문단을 AI가 쓰게 하려면 입력 |
| `LLM_PROVIDER` | `openai` | 선택 | LLM 키를 쓸 때만 |
| `APP_ACCESS_CODE` | 무작위 | LLM 키 사용 시 필수 | 실제 LLM 분석에 요구되는 추가 코드(과금 방지). 키만 넣고 이 값이 없으면 앱이 시작되지 않아요 |
| `MAX_LIVE_RUNS_PER_HOUR` | `10` | 선택 | 실제 LLM 분석 시간당 횟수(서버 전체) |
| `JOB_TTL_HOURS` | `72` | 선택 | 분석 결과 보관 시간 |

`PORT`는 Railway가 넣어 줘요(시작 명령이 읽어요).

**처음에는 LLM 키를 넣지 말고 mock 모드로 배포**하세요. 계산·표·Word는 LLM 없이 모두 동작하고, 키는 나중에 `OPENAI_API_KEY`와 `APP_ACCESS_CODE`를 함께 넣으면 돼요.

## 3. 배포 후 점검

**직접** 도메인을 확인한 뒤, 같은 점검을 배포된 서버에 실행해요. (`pip install requests` 필요)

```bash
python scripts/predeploy_check.py --url https://배포-도메인 --code 초대코드
```

수동 확인(5분):

1. `https://도메인/health`가 `{"status":"ok", …, "auth": true}`를 돌려주는지
2. 초대 코드로 로그인 → "4방향 샘플 채우기" → 분석 실행 → 결과·도표 확인 → Word 다운로드
3. 다른 브라우저(시크릿 창)에서 로그인 없이 `/app`이 로그인 화면으로 가는지
4. **재배포 후에도 결과가 남는지**: 분석 → Railway에서 재배포 → 같은 결과 링크(다운로드)가 살아 있는지(볼륨 확인)
5. Word 파일을 **직접 Word에서 열어** 표지·표·가로 쪽(별지)·목차가 깨지지 않는지 (제가 확인하지 못한 항목)

## 4. 운영

- **사용자 추가/제거**: Railway Variables에서 `BETA_CODES`를 수정해요. 설정은 앱 시작 시 한 번 읽으므로 **서비스가 재시작되어야 반영돼요**(보통 변수를 바꾸면 Railway가 재배포해요 — 반영됐는지 새 코드로 로그인해 확인하세요). 제거된 코드의 사용자는 로그인이 끊기고 그 사용자의 보고서에 접근할 수 없어요(보고서는 코드로 만든 사용자 ID에 묶여 있어요).
- **LLM 켜기**: 크레딧을 확인하고(지금 개발용 키는 잔액이 소진된 상태였어요) `OPENAI_API_KEY`+`APP_ACCESS_CODE`를 추가해요. 화면의 "실제 LLM 사용"에서 접근 코드를 입력해야 호출돼요.
- **로그 보는 법**: Railway 서비스 로그에서 `ConfigError`가 보이면 환경변수 규칙 위반이에요(위 표).
- **롤백**: Railway의 이전 배포로 되돌리기. 볼륨 데이터는 유지돼요.

## 5. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 배포 직후 헬스체크 실패/재시작 반복 | 로그의 `ConfigError` 확인: BETA_CODES·SECRET_KEY(32자)·APP_ACCESS_CODE 규칙 |
| 로그인했는데 곧바로 로그인 화면 | HTTPS가 아닌 주소로 접속(쿠키 Secure), 또는 SECRET_KEY가 바뀜 |
| "로그인 시도가 너무 많습니다" | 같은 IP에서 10분 안에 10회 실패. 10분 후 재시도(TRUST_PROXY=true가 아니면 프록시 IP 전체가 묶여요) |
| 재배포 후 결과가 사라짐 | 볼륨 미연결 또는 DB_PATH가 `/data` 밖 |
| 분석에서 "LLM 키가 설정되어 있지 않아…" | "실제 LLM 사용" 체크를 끄세요(mock) 또는 키·접근 코드 설정 |
| Word가 안 열림 | 파일이 0바이트가 아닌지, `python scripts/predeploy_check.py --url …`로 다운로드 점검 |

## 6. 이 문서에서 확인하지 못한 것

- Railway 대시보드의 정확한 버튼·메뉴 이름(문서의 설정 파일 키와 볼륨 제약은 공식 문서에서 확인했지만 화면은 직접 보지 못했어요).
- 요금: 플랜별 비용과 무료 크레딧은 확인하지 않았어요. 볼륨은 플랜에 따라 크기 제한이 있어요(Free/Trial 0.5GB, Hobby 5GB).
- 실제 Railway 환경에서의 실행(저는 계정이 없어 로컬 점검만 했어요).
