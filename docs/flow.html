2. 에이전트 파이프라인

① Planning — 대상 여부·범위 판정규칙 기반(LLM 없음) · 교통영향평가 대상 규모, 심의 주체, 평가 범위·반경, 별표 3 중점분석 항목
▼
② Data — 모든 숫자를 여기서 계산 발생교통량(원단위·재차인원·수단분담·유입/유출) · 주차수요(원단위법) vs 법정·계획 · 신호교차로 LOS(도로용량편람 2013 제8장 CASE 1~6) · 3단계 분석(미시행/시행/개선) · 개선 시나리오(녹색 재배분·주기·차로 증설·전용 좌회전·조합) · 설계 기준(좌회전 차로 길이 등) · 유의사항
▼
③ AI — 문단 작성 (LLM, 유일한 LLM 단계)"문제점 및 개선방안" 7개 항목. 입력은 [분석 결과] + [주차 판정] + [자료 없음] + [분석 시간대] + [개선 후보] + [설계 기준] + [유의사항]. 규칙 1~10 준수
▼
④ Engineering — 표·문서 조립LOS 표 생성 · 섹션을 별표 1 순서로 이어 붙임 · 없는 섹션은 [미작성]
▼
⑤ Reflection — 점검체크리스트 누락 · 정량 기준 판정 · LLM 문장 환각·해석 점검(3절)
문제가 있으면 (LLM 실연결일 때, 최대 재시도 횟수까지)
지적 섹션만 사유와 함께 재작성 요청누락 또는 계산과 불일치한 섹션만 다시 ③ AI로
④ → ⑤ 재실행조립 후 다시 점검 · 통과하면 종료

3. LLM 문장 점검 (facts.py · semantic_rules.py)

수치 점검과 의미 점검을 모두 통과해야 합니다. 실제 LLM 실행에서 찾은 오류 유형을 규칙으로 고정했습니다.

수치단위가 붙은 숫자는 계산 결과에 있어야 함 · 'LOS X'는 계산된 등급 · 용량 초과·포화는 v/c ≥ 1일 때만
주차계획 ≥ 법정이면 '부족'·증설 제안 금지 · 계획 미입력이면 부족·증설 모두 금지 · 법정과 원단위법 수요를 '초과'로 비교 금지(부정문·자전거 주차는 오탐 제외)
자료 없음대중교통·보행·자전거 이용 수준 단정 금지 → '현황 자료 없음, 조사 필요'
방향·시간대유입/유출을 시간 증가로 풀이 금지 · 분석하지 않은 첨두(AM/PM)의 지체·LOS 서술 금지 · 준공 연도(1·3년) 명시
